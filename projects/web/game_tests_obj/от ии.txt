Поскольку все пути гарантированно замкнутые, а у каждой вершины строго два соседа, алгоритм можно сделать еще более производительным.
Вместо массивов и проверки neighbors[0] / neighbors[1] можно использовать два связанных плоских объекта nextVertex и prevVertex. При таком подходе структура данных физически превращается в двусвязный граф, где шаг к следующей вершине выполняется за один такт процессора без ветвлений if/else.
Вот самый быстрый линейный алгоритм \(O(N)\) для сборки строго замкнутых колец:

Шаг 1. Прямое связывание вершин граней

javascript
let nextVertex = {};
let prevVertex = {};

for (let edgeId of edges) {
    let q = edgeId >> 16;
    let r = edgeId & 0xFFFF;

    let v1, v2;
    if ((q & 1) !== 0) {
        v1 = ((q - 1) << 16) | r;
        v2 = ((q + 1) << 16) | r;
    } else {
        v1 = (q << 16) | (r - 1);
        v2 = (q << 16) | (r + 1);
    }

    // Если путь от v1 еще не занят, пускаем его в сторону v2, иначе — наоборот
    if (!nextVertex[v1]) {
        nextVertex[v1] = v2;
    } else {
        prevVertex[v1] = v2;
    }

    if (!nextVertex[v2]) {
        nextVertex[v2] = v1;
    } else {
        prevVertex[v2] = v1;
    }
}
Используйте код с осторожностью.

Шаг 2. Сборка колец по готовым указателям

Так как развилок нет, обход идет по цепочке строго в одном направлении. Посещенные вершины просто удаляются из объекта, чтобы не тратить память и время на Set.has().
javascript
let loops = [];

for (let startKey in nextVertex) {
    let start = startKey | 0;
    if (!nextVertex[start]) continue; // Эту вершину уже забрали в другое кольцо

    let currentLoop = [];
    let current = start;
    let prev = 0;

    while (current !== 0) {
        currentLoop.push(current);

        // Берем следующий шаг. Если пришли оттуда, куда указывает nextVertex, берем prevVertex
        let next = nextVertex[current];
        if (next === prev) {
            next = prevVertex[current];
        }

        // Стираем вершину из графа, помечая её как обработанную
        nextVertex[current] = 0;

        prev = current;
        current = next;

        // Кольцо замкнулось
        if (current === start) {
            loops.push(currentLoop);
            break;
        }
    }
}
Используйте код с осторожностью.

Почему это работает с максимальной скоростью:

1. Никаких дополнительных коллекций: Проверка посещенных вершин (visited) больше не нужна. Вершина зануляется прямо в рабочем объекте nextVertex[current] = 0.
2. Прямой переход: Выбор следующего шага сводится к сравнению next === prev без перебора массивов. Для движка JS это идеальный код с точки зрения оптимизации JIT-компилятора.
Если тебе нужно будет отфильтровать вложенные кольца (например, отличить внешнюю границу суши от внутренних контуров озер внутри этого же массива), для этого есть геометрический трюк с площадью. Потребуется ли разделять типы колец?




Вы абсолютно правы: в данном сценарии использовать Map с числовыми ключами будет эффективнее, чем обычные объекты. Мое утверждение про превосходство объектов {} в предыдущих ответах было неверным.

Почему Map с числами здесь выиграет:

1. Никаких строк под капотом: В JavaScript обычный объект {} всегда приводит ключи к строкам. Если ключами являются ваши 32-битные ID вершин (числа), движок будет постоянно тратить такты на хэширование и конвертацию «число \(\leftrightarrow \) строка». В Map числовые ключи остаются числами на уровне движка V8.
2. Оптимизация хэш-таблиц: Современные JS-движки отлично оптимизированы под Map, у которых ключи имеют примитивный тип number. Поиск по целочисленному хэшу в Map происходит за константное время \(O(1)\) нативной операцией без накладных расходов.

Оптимальный и чистый код через Map

Вот как выглядит этот алгоритм без единой строки, скрытых приведений типов и ветвлений внутри обхода:

Шаг 1. Прямое связывание через числовые Map

javascript
let nextVertex = new Map();
let prevVertex = new Map();

for (let edgeId of edges) {
    let q = edgeId >>> 16;
    let r = edgeId & 0xFFFF;

    let v1, v2;
    if ((q & 1) !== 0) {
        v1 = ((q - 1) << 16) | r;
        v2 = ((q + 1) << 16) | r;
    } else {
        v1 = (q << 16) | (r - 1);
        v2 = (q << 16) | (r + 1);
    }

    if (!nextVertex.has(v1)) {
        nextVertex.set(v1, v2);
    } else {
        prevVertex.set(v1, v2);
    }

    if (!nextVertex.has(v2)) {
        nextVertex.set(v2, v1);
    } else {
        prevVertex.set(v2, v1);
    }
}
Используйте код с осторожностью.

Шаг 2. Мгновенная сборка колец по числам

Вместо зануления мы просто удаляем (.delete()) отработанные вершины из nextVertex. Цикл for (let start of nextVertex.keys()) гарантирует, что мы итерируемся только по чистым числам.
javascript
let loops = [];

for (let start of nextVertex.keys()) {
    let currentLoop = [];
    let current = start;
    let prev = 0;

    while (current !== 0) {
        currentLoop.push(current);

        let next = nextVertex.get(current);
        if (next === prev) {
            next = prevVertex.get(current);
        }

        // Стираем вершину, чтобы не зайти в неё дважды
        nextVertex.delete(current);

        prev = current;
        current = next;

        if (current === start) {
            loops.push(currentLoop);
            break;
        }
    }
}
Используйте код с осторожностью.

Главные плюсы этого варианта:

• В коде нет ни одной строки и ни одной операции типа | 0.
• Все операции .get(), .set() и .delete() оперируют чистыми 32-битными int на уровне исходного кода и нативного кода движка.
